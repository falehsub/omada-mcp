# Local review — 2026-11-14

The strongest direction is a dependable, easy-to-install Omada bridge for local
accounts, with useful diagnostics and demonstrably safe writes. This review
improves that foundation; it does not establish a popularity ranking or certify
every hardware/firmware combination.

## Scope and evidence

Reviewed configuration, authentication and HTTP transports, JSON-RPC dispatch,
read projections, pagination, write gates/recovery/snapshots, diagnostic helpers,
monitoring, packaging, CI, onboarding, and the roadmap. The starting branch was
`fix/live-lab-findings`, with a clean working tree at `a9d2f1e`.

| Check | Result |
|---|---|
| Baseline Windows / Python 3.10.11 suite | 170 passed |
| Final suite | 186 passed on Windows/Python 3.10.11 and Linux/Python 3.12.16 |
| Docker controller | `mbentley/omada-controller:6.2`, reporting `6.2.14.11` |
| Live Viewer doctor | All six phases passed, CA and SAN verification enabled |
| Live Viewer read sweep | 27 passed, 0 failed, 6 skipped |
| Live Admin read sweep | 27 passed, 0 failed, 6 skipped; writes remained disabled |
| Extra live scenarios | Events/audit logs; gateway/switch/EAP ACL reads; all 11 snapshot sections; client-inclusive topology; redirect session recovery; one-shot metrics; two watch iterations |
| Packaging | Docker image, wheel and sdist built; installed-wheel CLI and extracted-sdist tests checked |
| Static correctness | `ruff check src --select E9,F` passes |

The skipped tools were `get_device`, `get_client`, `get_switch_ports`,
`get_ap_radios`, `get_rf_scan`, and `diagnose_client`. The Docker site has no
adopted hardware or clients. Their behavior is covered by fixtures/mocks, not
new live hardware evidence. Live WAN/security/topology checks demonstrate
controller compatibility and missing-hardware fallback behavior.

All live controller requests used read-only configuration. The live sweep's
transport separately blocks every non-GET request except authentication. Write
flows, recovery and rollback were tested against the stateful mock controller.
No live controller configuration was mutated.

The controller worked inside Docker while its Windows-published HTTPS port
timed out. A temporary MCP container shared the controller's network namespace;
source, Viewer/Admin dotenv files and the CA were mounted read-only. TLS
verification stayed enabled. This isolates a host forwarding issue from an MCP
or controller defect.

## Findings fixed

| Priority | Finding | Change / regression evidence |
|---|---|---|
| P1 | Ambiguous write-disconnect errors included the query token | Errors retain the path only; a synthetic token never appears in the rendered error/endpoint |
| P1 | Snapshots, services and routing reads returned raw objects or relied on secret-name blacklists | Nested explicit field allowlists drop an injected unknown credential field while preserving documented diagnostic fields |
| P1 | Proxy fallback followed redirects with authentication headers | Redirect following disabled; loopback test proves the redirected endpoint is never requested |
| P1 | Two processes could overwrite a rollback snapshot for the same target within one second | Unique suffix plus exclusive file creation; both independently created snapshots retain their original contents |
| P1 | Requests without IDs could execute tools and emit replies; invalid envelopes were accepted | Reject invalid versions/IDs/params; ignore one-way notifications before controller I/O |
| P2 | Frame limit applied only after an unsuccessful decode and unbounded `readline` | Bounded reads reject oversized complete/incomplete frames and recover on the next line |
| P2 | Omada 6.2 expired tokens return HTTP 302 | Reuse the bounded session recovery path; GET replays once, writes require a state check and are not blindly replayed |
| P2 | Wi-Fi/wired limits were applied before filtering | Filter first, then return the bounded matching slice |
| P2 | Repeated client pages consumed the entire page budget | Stop on repeated pages and short pages without totals; reproduction falls from 20 calls to at most 2 |
| P2 | Invalid ports and non-finite timing values escaped validation | Actionable config errors; reject invalid CLI polling intervals before loading config |
| P2 | Source distribution omitted fixtures/mock support required by its tests | Explicit manifest includes tests, fixtures, schemas, scripts and Docker files |
| P2 | No automated static correctness gate | Focused CI gate catches syntax/name/unused-variable/import problems |

The new `scripts/read_selftest.py` reports only tool names, status, timing,
request counts and controller version. It deliberately excludes controller
payloads, network identifiers and account details. Setup errors direct the user
to the local doctor. A skipped check is not counted as a pass.

Diagnostic exports intentionally omit unknown fields. They are not full
controller backups. Write snapshots continue to serve the rollback mechanism;
changing diagnostic exports does not change the controller's write payloads.

The initial full Ruff run found 1,505 findings, mostly legacy typing syntax
(`UP006`/`UP045`). The five focused correctness findings were fixed. The full
configured lint rules are not clean; the new CI gate intentionally covers only
`E9,F`. Setuptools also warns about the legacy license table/classifier; migrate
to SPDX metadata with an appropriate build-backend minimum in a separate change.

## Positioning against existing projects

These are repository-stated features, not independent verification of their code:

- [MiguelTVMS/tplink-omada-mcp](https://github.com/MiguelTVMS/tplink-omada-mcp)
  documents broad Open API coverage, Docker distribution and HTTP transport.
- [dfla-me/omada-mcp](https://github.com/dfla-me/omada-mcp) documents guarded writes
  with preview/read-back verification over the Open API.
- [thalisantunes/mcp-omada](https://github.com/thalisantunes/mcp-omada) documents
  real OC200 testing and both local-account and Open API access.

My inference: the most defensible advantage here is the combination of local
Viewer access, zero runtime dependencies, verified TLS, task-level diagnostics,
and tested recovery/safety behavior. Extend that advantage with reproducible
compatibility evidence and installation quality. Tool count alone is a weak
product target.

The [MCP base protocol](https://modelcontextprotocol.io/specification/2025-06-18/basic)
requires valid request IDs and no replies to notifications. The
[stdio transport specification](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports)
defines newline framing. An official-client conformance matrix should supplement
the existing hand-written protocol tests before advertising newer revisions.

## Reproducing the checks

```bash
python -m compileall -q src tests scripts
python -m unittest discover -s tests -v
python -m ruff check src --select E9,F
python -m build
python scripts/read_selftest.py --env-file /path/to/isolated/viewer.env
```

Use an explicit isolated config for all live tests. When running the sweep in a
container, mount the source and lab config read-only and override
`OMADA_CA_BUNDLE` to its container path. Never use the production per-user dotenv.
